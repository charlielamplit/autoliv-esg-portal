## 1. 问卷样本解读（平台的"标准输入范式"）

Polestar SSI，发给 Autoliv 南京工厂（安全带）。结构五层，全部应被平台建模：

| 层 | 内容 | 平台对应 |
|---|---|---|
| 问卷元信息 | 客户、年度、联系人、CoC 链接、填写指南 | 问卷收件箱字段 |
| General Information | 工厂档案 + 能源活动数据（外购电 650万kWh、绿电 0…）+ 客户审核史 + 原材料供应商名单(Tier1-4) | **就是一次碳盘查+尽调数据采集**——平台档案库直接预填 |
| 问卷主体 | 5 支柱 × 112 题：气候中和 / 循环性 / 透明度(含CMRT) / 包容性(DEI+CoC劳工) / 环境管理体系与EHS；每题 = Yes/No/NA + 支持信息 + 行动计划 + 客户反馈栏 | 作答工作台数据模型 |
| 隐藏评分引擎 | 权重表 + 最低要求红线 + 4 类校验（未回答/重复回答/未填支持信息/未达最低要求） | 得分模拟器 + 完成度校验条 |
| 汇总页 | 分支柱得分 + 行动计划统计 | 分析屏 + 领导摘要 |

**核心洞察**：112 题中 ≥10 题直接考察 Autoliv 的上游传导能力（Q6 选商低碳标准、Q7 供应商培训、Q8 要求上游碳数据、Q16 供应链减排目标、Q62-68 冲突矿产尽调全组、Q72 上游是否 RMI 成员、Q81 供应商 CSR 现场审核、Q96 上游环境考核）——demo 答案里这些几乎全是"计划中"。**传导不是平台附加功能，而是把问卷答好的前提**；这是给 Autoliv 领导汇报的题眼。

## 2. 平台概念：问卷生命周期流水线

```
① 收件(多客户问卷涌入) → ② AI解析(题目/支柱/权重/红线)
→ ③ 能力匹配预填(平台数据 + 历史答卷复用)      ← 链主服务 I
→ ④ 差距分析(失分项/红线预警/分支柱得分模拟)
→ ⑤ 建议与行动计划(每个差距: 建议 + 平台能力匹配)
→ ⑥ 传导(依赖供应商的差距 → 数据请求单/培训任务/CMRT收集)  ← 复用 datareq 抽屉
→ ⑦ 输出(问卷回复文件 + 给领导的分析报告)        ← 复用 V5 向导模式
```

## 4. 新增 V7「客户问卷」三屏

### 7a 问卷收件箱 Survey Inbox
列表：客户（匿名徽章）· 问卷类型（SSI/SAQ 5.0/CDP/CMRT/自定义）· 收到日期 · 截止 · 完成度 · 当前模拟得分 · 状态（新收/解析完成/作答中/待传导/已提交/客户反馈）。顶部 KPI：在办问卷 n · 30 天内截止 n · 平均得分。空态文案强调"支持 Excel/PDF/平台直连多种问卷进件"。Demo 数据：客户P SSI（主角）+ 2-3 份陪衬（SAQ 5.0、CMRT 年度、某 OEM 自定义问卷），显示不同状态。

### 7b 作答工作台 Response Workbench（演示主屏）
三栏布局（沿用 Cockpit 卡片语言）：
- 左：支柱树（5 支柱 → 二级目录 → 题号），节点带完成度环 + 失分红点；
- 中：题目卡（编号/对象/题干中英/说明）+ 答案三态 + 支持信息 + 行动计划栏；预填题带"AI 预填"徽章 + 数据来源（平台模块/历史答卷/证据库）；
- 右：**AI 面板**（预置结果）——本题能力匹配（如 Q8 → 供应商碳数据采集模块）、历史答案复用（上一年度 Volvo 问卷同类题）、证据引用（ISO14001 证书、CoC 文本）；
- 顶部：四项校验条（未回答/重复回答/未填支持信息/未达红线），实时计数——**复刻 SSI 隐藏页校验逻辑，客户一眼认出"我们的问卷被理解了"**。

### 7c 分析与传导 Analysis & Cascade（给领导看的屏）
- 分支柱得分模拟：当前 vs 整改后（双色条）；最低要求红线预警区；
- 差距清单：失分题 → 每行 = 题号/权重/建议/**能力匹配**（平台哪个模块解决）/是否需传导上游；
- 需传导项一键动作：生成数据请求单（datareq）/ 供应商培训任务 / CMRT 收集任务；
- 底部"一页领导摘要"卡：得分、红线、TopN 差距、传导动作数、预计提分——可从 V5 导出。

### 抽屉
新增 `kind=survey`（问卷元信息 + 得分构成 + 提交历史）或复用 requirement 抽屉加 source 字段——倾向后者，改动小。

## 5. 数据模型草案（内嵌 JSON）

```js
survey: { id, customerAnon /*"客户P"*/, type:"SSI", received, due, status,
          pillars:[{ key, name, nameEn, weight, score:{now,potential},
            questions:[{ no, subject, q, qEn, guideline,
              answer:"yes|no|na", support, actionPlan, customerFeedback,
              weight, isMinimumReq, aiPrefill:{ matched:true, source:"platform|history|evidence", note },
              gap:{ advice, capabilityModule, cascade:{ needed:true, kind:"datareq|training|cmrt", supplierIds } } }] }] }
```

## 6. Demo 演示脚本（预置数字，演示口径）

1. 收件箱：客户P SSI 到达，112 题，截止 T+30；
2. AI 解析完成 → **自动匹配 87/112（78%）**：62 题平台数据直答、25 题复用历史答卷；剩 25 题人工，其中 13 题快速确认、12 题为实质差距；
3. 校验条全绿（0 未回答/0 重复/0 缺支持信息），红线 0 触碰；
4. 得分模拟：当前 71 → 完成行动计划后 89（分支柱展示，气候中和提升最大）；
5. 12 个差距中 **5 个依赖上游数据**（Q8 碳数据、Q64/65/67 矿产尽调、Q72 RMI 成员）→ 一键生成 5 张数据请求单，V3 供应商档案即时可见；
6. V5 一键导出《客户P问卷响应分析报告》给管理层。
（所有数字为演示预置，页脚标 Demo data；"87/112"与询价单"380→280"叙事同构。）

## 9. 现场演示策略（2026-08 现场交流用 · 四层动机 × 五幕动线）

**原则**：四层需求分析（省力 / 保订单 / 能力缺口 / 向上交代）是 demo 的**设计骨架**，不是现场台词。第 1-3 层可逐层讲明，**第 4 层只做不说**——"一页领导摘要"放在对接人眼前即可，绝不点破。

| 幕 | 场景 | 兑现动机 | 话术钩子 | 打动谁 |
|---|---|---|---|---|
| 1 痛点共鸣(30s) | 7a 收件箱：4 份不同客户问卷并列、不同截止日 | — | "这是贵司中国团队的日常" | 工作层点头 |
| 2 省力 | 7b 工作台：AI 匹配 87/112 · 校验条全绿 · 证据库自动引用 | 第1层 | "'见我们CoC'这类题，答过一次永远不用再答" | 实际填卷的人 |
| 3 分数与利害 | 7c 得分模拟 71→89 · 红线零触碰 | 第2层 | "SSI 说明第一条：这是采购绩效评估——这个数字是销售的数字" | 管理层/销售侧 |
| 4 **高潮(90s)** | 差距清单 Q8"计划中"→ 现场点「生成数据请求单」→ 跳 V3 供应商档案 | 第3层 | **"这题没法靠话术答，只能靠真做。用平台，明年这题从'计划中'变成 Yes——平台本身就是答案"** | 决策者（铺垫询价单③④） |
| 5 收口 | 7c 一页领导摘要 → V5 导出报告 → 切回 V1 总览结束 | 第4层(不说破) | 结束语落在"问卷→分析→传导→汇报"闭环，不落单点功能 | 对接人本人 |

**临场适配**：领导在场 → 三、五幕提前；仅工作层 → 按序走。全程 15-20 分钟，第四幕必须现场真点击（不是截图）。

**必被问的三题的口径（提前与销售对齐）**：
1. 自动匹配率承诺？→ demo 78% 为演示口径，合同口径由产品确认（勿现场承诺）；
2. 问卷数据放哪？→ 顺势接本地部署方案，回扣《区分报价_本地vs云端》；
3. 这个模块怎么收费？→ 回扣链主服务 I（AI 问卷映射）及定制开发起步价，由销售收口。
