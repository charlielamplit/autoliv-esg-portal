# V1 总览驾驶舱 · 优化需求

> 目标：按主线「**客户要求 ＋ 法规与管制（并列需求来源）→ Autoliv 自身响应 →（响应不了）向上游传导 → 监督上游回填 → 自身合规 ＋ 全价值链可持续合规**」，把 V1 从「客户问卷流水线」升级为「价值链合规管理驾驶舱」。**第一原则：整条流程完整，五段首尾相接。**
> **硬约定：全程不使用 emoji。** 状态一律用**文字 + 色块**表达——「就绪 / 待补 / 告警」（对应绿 / 黄 / 红，但以纯色圆点、色条或文字标签实现，禁止任何彩色圆点等 emoji 字符）。沿用结果导向口径：每段接**交付状态**，而非仅流量计数。

## 0. 这条主线（全 Demo 骨架，务必对齐）

```
需求来源：客户要求 ＋ 法规与管制（并列，均为需求来源）
   → Autoliv 自身响应（用自身体系 / 37 项 / 行业标准，能答的自己答）
   → 传导（答不了的缺口，向供应链上游下发）
   → 监督（跟踪上游回填与达标）
   → 达成（自身合规 ＋ 全价值链可持续合规）
```

V1 首屏 = 这条线的**地图 + 实时状态**。客户要求与法规管制**并列为需求来源，不分主次**；本次第一原则是**「流程完整」**——上面五段必须齐全、首尾相接、可点连贯；其中「监督回填」与「达成度」是当前缺失的两段。

## 2. 目标结构（V1 v2，从上到下四层）

### Layer A · 顶部横幅：达成度 + 总体态 + 今天最紧急 3 项

- **头号指标：价值链合规达成度**（自身合规 + 上游达标的综合），大号数字 + 进度条。
- **总体态**：就绪 / 待补 / 告警（文字 + 色块，非 emoji）。
- **今天最紧急 3 项**（可点进对应屏）：

### Layer B · 价值链合规主线（核心，替代现 5 格）

一条左→右脊柱，五段，每段 = 状态色块 + 关键数 + 点击进对应屏：

| 段 | 内容 | 关键数（示例，绑 state） | 去向 |
|---|---|---|---|
| ① 需求来源 | 客户要求 ＋ 法规与管制（**并列，不分主次**） | 客户 4 份在办 · 8 指标 ／ 法规 16 条 · 稀土倒计时 | V2 / V6·V8 |
| ② Autoliv 自身响应 | 能自答 vs 缺口 | 自答得分 X ／ 缺口 Y 条 | V11 |

> 这条脊柱就是给 Autoliv 用户「一眼看懂整体流程 + 当前状态」的地图。**流程完整是关键**：把法规并入来源、补上监督段、以达成度收口——正是当前缺的三处；五段要首尾相接、能一路点连贯。

按 客户 / 零件 / 材料 / 工厂 / 区域 下钻的合规档案入口。

## 3. 主线 vs 导览（回答「能否用导览替代」）

**结论：分工，不替代。**

- **主线（V1）** = 常驻的「地图 + 实时状态」：一眼看懂流程走向 + 现在每段什么状态。被动、随时可见。
- **导览（tour）** = 触发式「带你走一遍」：逐步演示每步怎么发生。主动、线性、一次性。

**建议**：保留 V1 主线，但重画为「价值链脊柱（来源→响应→传导→监督→达成）」；把现 5 格里「教学式逐步演示」的部分完全转移到导览。这样导览教「怎么走」、主线显「在哪 + 什么状态」，不重复。若要进一步精简，V1 主线可收成**一行紧凑脊柱条**，把首屏空间让给 Layer C 管理 KPI。

## 4. 状态与视觉（去 emoji 硬性要求）

- 三态一律**文字 + 色块**：就绪（绿）/ 待补（黄）/ 告警（红）——用 CSS 纯色圆点、色条或文字标签实现，**全屏禁止 emoji 字符**。
- 头号指标「价值链合规达成度」用大号数字 + 进度条。
- 倒计时用「距 X 日期 N 天」文字 + 色条，不用 emoji。

## 5. 数据与真实性

- KPI 绑 state（供应商 317 / $776M、高风险 47、未传导 67、下发 148、客户 4 份、法规 16、稀土窗口 2026-11-10）；勿写死字面量。
- hero 主行动按钮（导出简报 / 生成报告）接真跳转或 toast，别留死控件。
